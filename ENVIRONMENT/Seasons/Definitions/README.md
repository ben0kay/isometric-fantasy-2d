# ENVIRONMENT/Seasons/Definitions

Future data profiles (`Spring.tres`, `Summer.tres`, `Autumn.tres`, `Winter.tres`) should use a shared `SeasonDefinition` type once it exists. Suggested fields: relative temperature, daylight modifier, rain/snow/wind tendencies, growth coefficients, leaf-fall tendency. Climate/biome-specific overrides remain biome data; tree-specific seasonal art remains under `WORLD/Content/Vegetation/Trees/<Species>/`. Don't create empty .tres assets until a useful common schema is agreed.

> **Status:** Future architecture / folder placeholder only. No new production environmental mechanics are implemented in this folder.
