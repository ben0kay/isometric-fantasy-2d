# Shared rewards and physical pickups

Implemented H1–H4. Systems receive a canonical ItemCatalog and scope; WorldHarvestRuntime supplies production ownership without a global manager.

- DropEntry/DropTable: canonical item, minimum/maximum, independent chance; Compile produces a snapshot and stable per-source/reward-index rolls. Blank/invalid/cyclic item registration is handled by the existing catalog; invalid reward values fail setup.
- DropScatterProfile / DefaultDropScatter.tres: shared spread 58 units, hop 24, flight 0.55s, landing rotation ±25°, tumble up to ±120°, collection radius 60, caps 128 live / 32768 retained records / 16 per burst. Tune one Resource, not a file per item/tree. Values snapshot at coordinator setup.
- WorldDropSpawner: TryReserve event ID + rewards atomically, then Release once. Reserve validates all quantities/landing positions and caps before changing logical state. Failed/repeated source events cannot partially grant or reroll rewards. Small bursts split into one-unit pickups; larger rewards coalesce to actual stack limits. CaptureSaved returns detached uncollected outcomes for campaign persistence.
- DroppedItem.tscn/cs: grounded/Y-sorted root and static shadow; optional item WorldSprite with Icon fallback, WorldSize and AllowWorldRotation. Only artwork rises/spins; root moves along the ground. Once settled, both processing callbacks are off. No rigid body, per-pickup Area2D, global scan, expiry timer or ambient animation.
- Collection: explicit request from PlayerPickupInteraction. Searches nearby spatial buckets and line of sight, then performs canonical InventoryStorage.TryAdd. Airborne, obstructed, out-of-range, dead-player, mismatched-catalog and full-inventory requests fail without consuming anything. Repeated/reentrant requests cannot double-grant. Partial acceptance is intentionally unsupported.

IDs derive from scope/source/completion + reward/piece index. Production sources retain felled tombstones to prevent rerolls, allowing collected drop records to be pruned. Standalone fixtures keep a bounded consumed-event journal.

World streaming keeps logical records by final landing chunk and materializes only loaded owners. Reloaded drops settle without replaying the hop. New bursts respect the 128 active budget; returning to existing saved piles materializes all their records, even above that new-spawn budget, so items are never silently hidden or deleted. Total logical records remain bounded at 32768. Offscreen records have no processing/physics Nodes. Source completion and reward reservation precede the visual fall; saves during it recover the chosen outcomes. Collection marks the logical record before storage Changed notifications, so observer captures remain coherent. [H4 integration](../Harvesting/H4_World_Validation.md).
