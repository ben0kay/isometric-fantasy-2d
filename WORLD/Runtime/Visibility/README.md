# Shared scenery visual bounds

`SceneryVisualBounds` supplies transformed artwork and camera rectangles to existing production adapters. Trees, rocks and future static scenery use the same `Sprite` template convention; no per-species scene, ticking node or name branch is added. Sprite offsets, root scales/mirroring and container transforms are included. A future template with several visuals or a different sprite path must extend this shared bounds contract and the existing adapters together, rather than quietly bypassing registration.

EnvironmentMasterConfig controls `CullOffscreenSceneryEffects`, `SceneryPrepareMargin` (160 units) and `SceneryRetentionMargin` (96 units). Per-chunk wind/wetness/snow updates pause outside the union of its actual artwork plus these margins. Wetness and snow resume from the authoritative world values; wind is refreshed before drawing. Culling does not change generation, stable IDs, collision, player-behind-tree fading, burn progression or chunk ownership. Godot handles ordinary off-screen sprite rasterization; this pass reduces custom CPU cosmetic updates, not all node processing.

Sun casters use separately cached conservative artwork reach multiplied by current projection length. This deliberately retains off-screen trees whose shadows may enter the view. Dynamic actors refresh their bounds every frame; static scenery refreshes on appearance changes. Contact/projected shadows start hidden and never interpolate. Chunk roots/ground also disable interpolation, preventing static streamed artwork from interpolating from an initial identity transform.

Static scenery is assumed not to move after registration. If a future mechanic moves/resizes it, add an explicit bounds invalidation/re-registration call; do not give every static prop a processor. Keep shader displacement within the configured conservative margins. Camera rotation/zoom/resizing are included in view queries, but streaming's separate maximum-view validation still applies.

This is cosmetic scheduling, not A-Life. Local torch lights/native occluders and active burning effects retain their existing lifecycle and engine culling. Fine-grained individual sprite hiding, general local-light LOD and GPU shader prewarming are not implemented here.

`SceneryArtworkIndex` is the shared static artwork exclusion index for surface effects and lightning ground targeting. It has no processing callback and no dependency on rain presentation. It caches changed scenery incrementally, uses 256-unit spatial buckets and exposes bounded point queries plus dynamic player bounds on demand. EnvironmentRuntime owns the production index; rain and lightning consume it independently. It is not a general physics/navigation index. Call the explicit scenery refresh lifecycle when static artwork moves or changes.

## P2-A / P2-B spatial scheduling — implemented

SpatialBoundsIndex<T> is reusable world-scoped cached rectangle data, not a scene/physics manager. It supports negative cells, overlapping/large art, updates/removal and reusable query buffers. Normal queries visit nearby buckets; artwork spanning more than 256 cells uses a separate spill set, and queries spanning more than 4096 cells scan cached entries rather than millions of empty cells. Those exceptional paths remain proportional to registered data. Registration/update/remove are explicit; no per-prop process is added. Chunk cosmetics use 1024-unit cells; occlusion uses 256-unit cells. These cell sizes do not change the streamer's 512-unit world chunks.

EnvironmentRuntime queries nearby prepared chunks plus its current active set, preserving prepare/retention hysteresis. Distant inactive chunks are excluded from normal per-view decisions. Unchanged views/settings skip chunk checks. SceneryVisibilitySlack defaults to 32 world units: evaluate a slightly expanded window early, then reuse it while the current prepared view remains fully enclosed. This cannot delay entry into the actual prepared view; it may retain/activate a few extra cosmetic chunks. Zero slack restores exact view checking. Camera jumps/zoom/resizing outside the envelope, settings changes, new chunk registration and explicit scenery-bounds refresh remain responsive. Newly added/refreshed chunks use the same cached envelope so later movement inside it cannot miss them. Culling OFF wakes all registered cosmetics once and skips camera-driven checks while OFF. Shared wetness is cached rather than searched on every transition.

VisibilityPasses/VisibilityChunkChecks expose actual decision work. LastVisibilityMilliseconds still includes the lightweight view/settings probe. Old sun-shadow relevance/caching is unchanged; this does not disable physics, session state, simulation or all off-screen node activity. Explicit RefreshScenery updates changed chunk art bounds; moving static art must use that lifecycle hook.

ValidateSpatialScheduling passed 32 checks, including reserve/exact mode, hysteresis, camera jumps, negative/large index cases, nearby detection, fades/restoration and cleanup. See FEEDBACK/Visibility/README.md for occlusion behavior. Target-machine visual/FPS validation remains separate.
