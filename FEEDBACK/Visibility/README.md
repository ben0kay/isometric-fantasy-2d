# Shared player occlusion fading

`OcclusionController` is created once by `WorldScene`; it tests opted-in registered world tree visuals against the player. Tree definitions expose an `OcclusionProfile` (default enabled), with minimum alpha, fade-in/out rates and visual padding. All generic trees use it with no species-specific scenes/scripts. The controller processes only active fades and checks spatial candidates periodically; there are no per-tree `_Process` loops.

The fade applies to the tree Sprite2D `Modulate.A`, preserving its existing material, wind, snow, burn/charred child visuals and node collision. On restoration/unload the original alpha is restored. Other props can opt in later by registering their visual node via `Register` or by exposing a generic occluder wrapper; the shared detection/fade controller is not tree-specific.

Occlusion is based on visual bounds and world Y depth: only tree art covering the player's approximate upper-body point while the player stands behind the tree trunk is faded. This deliberately does not fade nearby trees which aren't blocking the player. The first release is a bounded box approximation; a future foliage mask may refine irregular silhouettes.

## P2-B implementation details

Registered visual bounds (including offsets, scale/mirroring and profile padding) enter a world-scoped SpatialBoundsIndex. The shared player-position probe remains each frame; ordinary moving-player detection retains the 0.10-second cadence, with source/profile changes and large teleports able to refresh immediately. An unchanged player/source state performs no new detection query. Only nearby bounds candidates plus previously obstructing visuals are tested; the latter ensures moving/teleporting away restores old blockers. Visible-in-tree checks exclude hidden/unpublished chunk roots, and the original behind-anchor rule remains. This is still a rectangle approximation, not texture-alpha masking.

Only entries actively changing opacity are visited for interpolation; settled alpha makes no material/tint writes. Fade endpoints snap to exact target alpha. Unregister/controller exit restore the captured original alpha, disconnect events and remove spatial/fade references. Last-entry removal sleeps the controller. Profile setters emit Changed so live edits update settled blockers. Source visibility/rect/lifetime and active hit-transform events refresh only the affected bounds. Non-static opt-in owners refresh moving bounds at the shared check interval; static transforms edited externally must call Refresh(visual). No per-species scenes or per-prop idle processors are added.

Counters RegisteredCount, ActiveFadeCount, DetectionPasses, CandidateChecks and FadeWrites support validation. ValidateSpatialScheduling passed 32 checks; the fixture includes 250 distant blockers while nearby checks stay below 10, exact non-unit source alpha restoration, stationary idle, front/behind depth, hidden ancestors, profile changes, teleport, unregister/source removal and moving generic props. Existing streamed visibility/cancellation and P3 suites also pass.

## Planned follow-up — silhouette-aware occlusion (Codex handoff; NOT IMPLEMENTED)

**Reported visual bug (2026-10-22):** In the Pink Meadow, a blossom tree fades even when the player stands visibly beside its branches, rather than behind its artwork. The sprite has large transparent regions. Current `OcclusionController.Refresh()` indexes `SceneryVisualBounds.Sprite(visual).Grow(profile.VisualPadding)`; the narrow-phase obstruction check only tests whether the player's approximate upper-body point lies inside **that rectangular world-space bound**, plus the existing behind-anchor Y rule. Transparent parts of the sprite therefore cause false-positive fading. This is a known limitation, not evidence that the spatial index is malfunctioning.

**Proposed fix — retain cheap rectangle broad phase, add artwork-aware narrow phase:**

1. Keep the existing shared `SpatialBoundsIndex<Sprite2D>`, registration/unregistration, event-based bounds refresh, player depth test, bounded detection cadence and active-fade-only interpolation. **Do not** revert to scanning every tree or give trees individual `_Process` callbacks.
2. For nearby rectangle hits only, transform player visibility probe point(s) from world coordinates into the sprite's **texture pixel coordinates**. Correctly account for Sprite2D position/global transform, centering, offset, scale, negative/mirrored transforms and `FlipH`, as well as any source atlas/region geometry if used. Reject transparent artwork rather than treating the full rectangle as opaque.
3. Prefer a **cached, CPU-side alpha occupancy mask** per distinct texture/region (or shared authored visual variant where necessary) with a small adjustable alpha threshold. Build/load it once, reuse across the many tree instances; never read pixels from the GPU, call `Texture2D.GetImage()` per candidate/per frame, or allocate arrays during routine checks. Document Godot imported/compressed texture access and memory tradeoffs; consider a coarser downsampled occupancy grid if exact pixels are too costly.
4. A single point can miss an actual branch obscuring the player's sprite. Test a small fixed number of upper-body probes or a narrowly bounded body region; keep this optional/configurable and benchmark candidate cost. Avoid fading when just the player's feet are near trunk art. Preserve front/behind Y behavior, natural wind/hit wobble response, fade durations/minimum alpha, charred art and exact alpha restoration.
5. When artwork switches (variant, burnt/charred state, texture/region) or transforms change, invalidate/rebind the corresponding cached visual metadata and bounds via existing signals/lifecycle. Streamed chunk load/unload must clear **instance** references while shared cached masks remain bounded/reusable. Preserve all generic species; no special-case blossom/oak code and **no new per-tree hit-mask resource file**.
6. If wind shaders can visually displace foliage, test a conservative sampling margin or clearly document remaining differences between CPU mask and shader-displaced pixels. Do not silently change rendering order, tree collision, existing wind, or shadow handling.

**Acceptance / test cases:** At the screenshot-like offset, standing in transparent sprite padding **must not fade** the blossom tree. Move the player's upper body behind opaque leaves/branches and fading **must** start; leaving restores exactly the previous alpha. Verify two existing tree types, mirror/scale/offset/variant, near-edge probes, tree in front vs behind, charred/no-foliage appearance, F9/profile changes if available, moving/teleporting player, stationary idle, chunk unload/reload and camera zoom. Capture `CandidateChecks`, `DetectionPasses`, `FadeWrites`, elapsed CPU time and allocations with many trees; when stationary there should be no repeated mask generation or new all-tree scans. Check visual behaviour in Godot on the target machine; do not claim FPS gains without measured evidence.
