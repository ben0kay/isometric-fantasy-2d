# Melee contact queries

C2 `MeleeHitQuery` uses the current physics world's overlap broad phase only during an active contact window. There is no group/world scan or idle Area2D. A cached circle/parameters excludes the source body. Radius adds a 64-unit conservative margin; actor hurt radii clamp to 3–60 independently from existing movement colliders. Nearby candidates then pass current hurt-point reach, locked-aim arc, faction/liveness and obstruction-ray checks. Default attacks select the nearest eligible actor or enabled tool helper; multi-target profiles select the nearest **up to MaxTargets** eligible actors in a single query. Equal-distance ties use instance ID. Tools receive at most one hit per swing (only if nearer than the closest selected actor).

Only immediate tool-helper children of nearby physics bodies are examined. This reuses tree `IToolHitTarget` feedback without sending actor damage to trees. Collision layers/masks, trunk shapes and scene ownership stay unchanged. Non-colliding props are not melee candidates. Walls and rocks still block all melee. For **multi-target cleaves**, actors do not obstruct each other, allowing clustered enemies to be hit; for single-target attacks intervening bodies still block as before.

At most 256 bodies are returned. A saturated query fails closed, increments `OverflowCount` and damages nothing; it never chooses an arbitrary truncated subset. `QueryCount` supports idle/active diagnostics. Cached native shapes/query parameters are disposed with the owner; active Godot query result arrays/dictionaries still allocate, so this is bounded active work, not a claim of allocation-free contact. Query cost depends on nearby physics density, not world size. See [C2 validation](../C2_Validation.md).
